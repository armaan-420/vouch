# Vouch release — Sites version 30

## 2026-11-03 — Version 30: collections, photos, water bottles and reliable saving

Published documentation: 2026-11-03. Catch-up covers Sites versions 19–30 since version 18 / `964eed08e54bb59026daa81ac102e55ddd7f8713`, including source and working-tree inspection. Latest application source: [33c860e](https://github.com/armaan-420/vouch/commit/33c860ed30ecf63311a8a9b8dbf0dfb84fc406f3). The application worktree was clean before this documentation update. Sites version 30 deployment `appgdep_6aea1d66e860819193ac5939e551e597` succeeded on 2026-11-03 12:44 PM America/New_York; environment revision 3. Saved versions were inspected: version 23 has no deployment attached; this catch-up describes the final version 30 behavior, without claiming each intermediate version went live.

### Collections and profiles

- Owner collections and public profiles lead with photo, display name, join date and a short bio. Item vouches appear in counts, category collages, category detail and history. Passes and brand trust remain stored and editable under All your answers.
- History retains the first item-vouch date and folds groups after the newest two. Each history/category-detail row shows the current community score from that item's source experiment, not its score on the vouch date or a personalized fit score. No votes shows Unrated; unavailable source data shows a dash.
- Edit profile uses a mobile sheet or centered desktop dialog. Display names accept 2–60 characters; bios up to 160. Cancel discards unsaved drafts.
- JPG, PNG and WebP photos up to 5 MB are center-cropped to 400×400 PNG in the browser. Server validation strips ancillary metadata; hosted images use R2 with opaque references in D1. Photo and profile fields save together. Photo reads recheck ownership/profile visibility and use no-store responses.
- Profiles and new opinions remain private by default. Public profiles include only public item vouches, published identity fields and safe history metadata. Private profiles/photos return 404 to other visitors. Product contributor pages still distinguish consenting item vouches, passes and brand trust.

### Reliable account saving

- New signed-in answers save directly to the account, including on a fresh browser and the first answer creating a browser cookie. No previous claim is needed for that answer. Unrelated anonymous history is not swept into the account.
- Existing opinion visibility is preserved; new opinions remain private even on a public profile. A partial save failure explicitly distinguishes a saved experiment answer from an account save requiring retry. Retrying does not duplicate votes.
- Contextual collection links preserve the current experiment. Earlier responses missing from the account can be reviewed and claimed using the same browser and exact-snapshot ownership flow. Generic /account cannot discover another browser's anonymous round.
- Email authentication, logout/expiry and account-switch isolation remain in place. Email control is not proof of purchase, expertise or Wharton affiliation.

### Water bottles and organizer tags

- [The Wharton Water Bottle Edit](https://v4ch.app/waterbottle) is available with nine stable product identities and checked-in photos: Owala, Hydro Flask, Stanley, YETI, Nalgene, CamelBak, Klean Kanteen, S’well and Takeya. The public configuration checked today is open, unscheduled and excluded from the overall board. Availability is separate from recruitment, a completed weekly drop or results.
- Bottle lookup stays in the bottle category; sunscreen nominations cannot select bottle SKUs. Additive photo backfill preserves existing custom images, votes, IDs and experiment settings. Other categories still need appropriate products and lookup validation.
- Product library & tags lets organizers search known products, create global/category definitions and assign up to 30 tags to a canonical product across experiments. Existing tags and assignments are preserved.
- Seed definitions include five global tags, nine bottle tags and fourteen sunscreen tags. No product is automatically tagged. Tags are organizer curation, not participant votes, verified testing, public filters or badges. Formula/water-resistance assignments require product-label evidence; Viral has no implemented evidence rule.

### Catalog and participation

- The checked-in sunscreen catalog grows from 829 to 2,201 listings: 1,371 retailer additions plus Lion Pose UNGHOSTED SPF 42, searchable by the former Ghost-Buster name. Sources added: Ulta Beauty 423, YesStyle 217, Care to Beauty 485, Dermstore 224 and Soko Glam 22.
- New shipped listings merge into saved catalog storage without rewriting experiment/account records. Retailer imports are snapshots; recurring brand/Open Beauty Facts feeds continue refreshing. Twenty matches are shown at most.
- YesStyle coverage stopped after rate limiting; Sephora and Olive Young blocked automated access; Target was not imported. Configurable mixed-formula cards and unidentified Dermstore brands are excluded. Counts represent listings, not unique verified formulations; differently named or regional duplicates may remain.
- Voting shows a quiet Standings link and product-only progress. Optional nominations follow the last answered product. The final action saves selected nominations before opening standings; failures retain selections. Nomination labels avoid repeated brand names and direct standings links load saved nominations.
- The root [v4ch.app](https://v4ch.app/) now presents the Coming Soon brand teaser. Dedicated experiment links remain /sunscreen and /waterbottle. Scoring mathematics, browser deduplication and voluntary signup remain unchanged.

### Reliability fixes and checks

- Voting uses a bounded JSON reader before writes; oversized streamed bodies return 413. Authentication reuses identity within one request while checking stored session validity on every new request. Activity writes are coalesced; idle expiry can be up to one minute early.
- Public voting/polling no longer performs organizer taxonomy checks. Search reuses a catalog-revision index and retries initialization after transient failure. Standings images load lazily; two large PNGs were recompressed without changing decoded pixels.
- Fresh verification for this publication: 71 automated tests passed, zero failures; git diff whitespace check passed. Tests cover account ownership/privacy and fresh-browser sync, retry/recovery, score provenance, bottle isolation/backfill, tags, catalog persistence, photo validation and existing experiment behavior.
- Sites confirms the version 30 production deployment succeeded. Public HTTPS configuration confirms the nine-product water-bottle lineup, photos and operating status. No production votes, account records or organizer settings were modified for this documentation update.
- Retained implementation reports record local Cloudflare/D1 account smoke tests, local R2 photo/privacy/removal checks and responsive browser reviews. Those are prior local checks; a fresh full production browser/accessibility audit was not performed today.

### Material limitations and next checks

- Real production inbox delivery/full code sign-in and a real signed-in production photo upload remain unverified. Failed-network photo recovery and screen-reader behavior were not fully browser-audited.
- Accounts/auth and experiments still use large optimistic JSON records; normalized indexed storage and load/abuse testing remain needed before broad scale.
- Anonymous scores count browsers, while public contributor lists count consenting accounts. A pass does not establish use; brand trust is separate from item experience.
- Signup conversion instrumentation, validated pilot outcomes, retention/purchase impact and commercial demand are not established. Following, feeds, advanced reputation, suggestions, discounts, moderation and account deletion/export interfaces remain outside this release.
- Original research, transcripts, decks, source attachments and earlier release entries are preserved. Commercial ideas remain hypotheses; human judgment remains the recommendation authority.
