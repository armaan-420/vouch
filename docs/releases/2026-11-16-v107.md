## 2026-11-16 — Version 107: simpler sign-in with a responsive polaroid fan

Published on November 16, 2026 (America/New_York). [Open sign-in](https://v4ch.app/account?signin=1).

### Sign-in changes

- **A cleaner phone screen.** Phones below 768px show the welcome eyebrow, “Your taste. Your people.” headline and email form without product imagery. The extra space below the headline is removed, and the email field now says “Enter your email address.”
- **Product polaroids on larger screens.** Tablets at 768–899px show a compact fan to the right of the headline, behind text where they overlap. At 900px and above, the fan sits in a warm paper panel beside the form. The same layout serves email entry, code entry, create account and pending verification.
- **Clearly illustrative activity.** The fan uses static fictional first names and initials with Stanley IceFlow, Owala FreeSip and Hydro Flask Wide Mouth. Jon’s pass has an outline tag; Maya’s 9.1 and Priya’s 8.7 are sample scores. “Sample activity” stays visible when the fan is shown. No accounts, visitor records or real votes supply these examples.
- **A clearer code step.** The heading changes to “Check your email.” and receives focus. One real numeric input appears as six cells and retains paste, one-time-code autofill, automatic submission at six digits and the manual verification button. Sending shows “Sending…” with a busy state. Resend opens after 30 seconds on both client and server; ten-minute expiry, verification attempt limits and hourly send caps remain.

### Catch-up since version 104

The approved italic-v logo rollout already deployed in version 106 is retained: the tilted lime emblem, lowercase wordmark, outlined placeholder glyph, favicons, Apple touch icon and web manifest replace the former asterisk treatment. Version 105 is saved without an attached deployment; version 106 has a confirmed successful deployment.

### Checks and limitations

All **309 tests** and the clean release checkout’s production build pass. Local browser checks cover phone, tablet and desktop widths, code autosubmit, signup/profile, returning sign-in, pending verification, resend and Change email. Final responsive checks cover 320, 393, 767, 768, 834, 1024 and 1440px; no horizontal overflow was found. The email button remains visible after focus in a 393×500 simulated keyboard viewport.

Read-only production browser checks confirm the final responsive layout, generic placeholder and absence of the local test inbox. Seven public/auth routes return 200; anonymous organizer inventory returns 401. Six deployed assets exactly match the checked source. Auth status reports available=true and previewDelivery=false; this confirms configuration, not inbox receipt.

Actual production inbox delivery/code verification, a physical mobile keyboard and a full screen-reader audit remain unverified. No production account, vote or other private record was created or changed during verification. Lint was not rerun; version 104 recorded four existing D1 typing errors.
